# Lunch-poll art-editor contract break

The lunch poll's cuisine art used to be generated by a `GeneratedArt`
sub-pattern instantiated inside every option card, each carrying its own
`fetchBinary` graph even while dormant, and each card published that
generator's lifecycle as `artSyncState`. PR #6795 moves generation to one
parent-owned editor that the host opens from a card's "generate art" control.
The checker exemption is recorded in `tasks/pattern-compat-accepted-breaks.ts`
and the vintage exemption in `tasks/pattern-vintage-accepted-drops.ts`; this
file records why those precise paths were accepted.

## The decision

A card row no longer contains a generator, so it has no generation lifecycle
to publish. The honest values of `artSyncState` on the new card would be
`"stored"` for a row with a persisted image and `""` for every other row.
Nothing in the repository read the field. The first version of the change
kept it anyway and answered `"generated"` for card instances deployed under
the old contract, purely so that a pinned vintage's non-empty leaf stayed
non-empty under the Tier 2 gate; that published a value that was false of
those rows. The field is retired instead, and the two gates record the
removal as the decision it is.

## What broke, on purpose

The compatibility checker reports one path over the two recorded card
contracts (`20260729T022742Z-FzI6KTHR_TQ4QStb` and
`20260821T000143Z-EHrqoO5qAEz6rL_W`):

- `lunch-poll/poll-option-card.tsx` removes the published `result.artSyncState`.

The argument side is compatible and needs no exemption: the old per-row
inputs (`removeConfirmTarget`, `removeOption`, `setOptionImage`) are removed,
which is compatible for optional-or-superseded inputs, and the new parent
request streams are optional with a defaulted scalar (`parentOwnsEditors`)
that tells an old instance apart, so it hides the two controls it could not
dispatch. Making those streams required was tried and refused by the vintage
replay (`missing required property requestRemove`), which is why they are not.

The Tier 2 gate replays the pinned 2026-07-30 lunch-poll vintage, whose card
rows hold `artSyncState: "generated"` from the host client's per-row
generator at capture time. Under the new source that leaf reads empty, and
the accepted-drop entry names exactly that path, bounded to vintages captured
through that stamp.

## What deliberately did NOT break

The durable art state was never on the card. A kept thumbnail is persisted
as `options[].imageUrl` on the parent by the host's explicit keep action,
which still sends the same `setOptionImage` event; every viewer renders that
stored value, and a card with a stored image renders it directly with no
generator at all. The vintage replay shows the parent's stored rows
surviving whole.

## Disposition of deployed pieces

No fresh piece is needed. The root contract (`lunch-poll/main.tsx`) applies
over its recorded baseline, so `cf piece setsrc` accepts the swap on a
populated poll. Card instances are derived sub-pattern targets: the updated
parent re-runs its map and re-supplies every card's arguments under the new
contract, which the vintage gate reports as "stored arguments superseded".
An old card instance only ever runs under the new source in the window
before that re-supply, and the defaulted discriminator keeps its controls
hidden for exactly that window.
